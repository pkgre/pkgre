# pkgre-rust

Transactional declarative reconciler + deterministic renderer for schema-5 pkg.re Cargo registries/categories.

## Interface

```text
pkgre-rust update-plan <catalog> <new-admission-manifest>
pkgre-rust update-plan-exact <catalog> <package> <version> [<package> <version>]... <new-admission-manifest>
pkgre-rust update-inspect <catalog> <admission-manifest> <package> <version> <new-review-directory>
pkgre-rust update-apply <catalog> <admission-manifest>
pkgre-rust lock <catalog>
pkgre-rust check <catalog>
pkgre-rust check-serve <catalog> --delivery=<body|redirect> [--archive-store=<directory>] [--first-party-origin=<url>]
pkgre-rust render <catalog> <output>
pkgre-rust verify <catalog> <output>
pkgre-rust verify-monotonic <previous-site> <next-site>
pkgre-rust migrate-v4-to-v5 <schema-4-catalog> <new-schema-5-catalog> [--git-tag-time=<registry>/<name>@<tag>=<timestamp>]...
pkgre-rust migrate-retained-delivery <catalog-root>
pkgre-rust archive-inventory <catalog> <output.json>
pkgre-rust archive-import <archive-store> <catalog>
pkgre-rust check-transition <accepted-catalog> <candidate-catalog>
pkgre-rust reproduce-git-tags <accepted-catalog> <candidate-catalog>
pkgre-rust self-publish-check <repository> [<accepted-repository>]
pkgre-rust self-publish-lock <repository>
pkgre-rust self-publish <repository> <tag> [--upload] [--git=<url>]
```

- `update-plan`:evaluate all active mirror compatibility lanes; create an absent compact canonical manifest containing every nonblocked exact request.
- `update-plan-exact`:evaluate one or more reserved mirror name/version requests, including new/inactive names, prereleases, and stable `0.0.x`; create an absent canonical manifest, planning every request as if it ran alone and refusing the whole batch when any request fails.
- `update-inspect`:recompute one manifest request + materialize checksum-verified candidate/base archives and bounded inert evidence without executing package code.
- `update-apply`:recompute every exact request at current time; reject young/yanked/blocked/invalid candidates; atomically install declaration additions, source rows, registry locks, canonical download catalog, and one immutable human-manifest/generated-lock admission pair.
- `lock`:preflight locally, refusing a lock whose recorded `audience` or mirror `admitted-at` no longer matches the declaration or the retained source row; reconcile initial bootstrap, empty reservations, removals, new first-party Git tags, and canonical `downloads.json`; direct new-mirror admission fails once registry locks exist.
- `check`:local-only strict schema/category/registry/audience/admission/download/object/hash/row validation that re-derives every mirror `admitted-at` from its retained source row, routed-row hash + dependency-edge validation, and a serving projection under the production limits; reports each limit it has half spent as `name=usage/limit`; never fetch crates.io or reproduce Git tags.
- `check-serve`:build the immutable serving snapshot of `<catalog>` exactly as the serving origin builds it, without serving or writing anything: the same delivery-mode spellings, first-party-origin rules and production projection limits, and body delivery's hash-verified archive bodies, so it fails exactly where a reload would fail (body delivery without `--archive-store`, redirect delivery without `--first-party-origin`, an invalid catalog, a failed limit, a missing or mismatched body); an option the selected mode does not use, a repeated option and an unknown option are refused; on success it logs the snapshot's inline, archive and redirect route counts.
- `render`:write a new complete site tree. Catalog registry `main` renders at the site root; other registry aliases render below `/r/<alias>/`; output must be absent.
- `verify`:re-render + require exact entry/byte equality with an existing site.
- `verify-monotonic`:permit registries/categories/package identities to be added, `active→removed`, and exactly the one-way `dl` migrations `check`, `lock` and `check-transition` allow (publish→mirror, source-specific→exact-router, exact-router→same-host native); reject removal/mutation/reactivation; authenticate exact release-manifest schema-2→3 + schema-3→4 migrations.
- `migrate-v4-to-v5`:parse every generated schema-4 lock strictly (exact fields, `schema = 4`), the schema-1 download catalog strictly, and every registry + external category file, refusing one whose `schema` is not 4; rewrite those files to schema 5 with `audience = "public"`; rebuild every lock with one `admitted-at` per package (crates.io row `pubtime`, or a required `--git-tag-time=<registry>/<name>@<tag>=<timestamp>` per Git tag, which is the operator's value and is not verified); replace the download catalog with the schema-2 `redirect` delivery model; write only to an absent destination, by migrating into a private staging directory beside it and renaming it into place only after the output was strictly loaded, policy-checked, artifact-verified and test-rendered, so a failed run leaves no destination; the source is never modified.
- `migrate-retained-delivery`:add `delivery = "retained"` to every root registry in place and rewrite `downloads.json` to the exact derived schema-2 bytes; archive bodies are imported separately and deliberately not verified here.
- `archive-inventory`:write the canonical retained-object inventory of one catalog for an archive store.
- `archive-import`:require the store's canonical `inventory.json` to equal the catalog's retained set, copy every missing `<sha256>.crate`, verify every digest, then re-run strict load/policy/artifact checks.
- `check-transition`:strictly load + policy-check accepted and candidate schema-5 catalogs; reject an added or removed registry, a changed registry name/index/audience/cargo-version, a download change other than the allowed one-way migrations, a missing identity, a changed archive/source-row/routed-row hash, source, `admitted-at` or admission binding, a state change other than `active→removed` (reactivation included), a moved category, a changed or removed accepted admission manifest/lock pair, a crates.io identity new since the accepted catalog without a binding to an admission batch that is new in the candidate, a changed or removed accepted category `may-depend-on` rule, and a moved or removed accepted package home; require every active retained identity's body to exist in `objects/crates/` with a matching SHA-256. It does not compare `delivery`, read row objects, or verify archive bytes beyond that retained-body check. A failed load names its side: a candidate catalog that its own bytes make unloadable is `candidate-catalog-invalid`, an accepted catalog that no longer loads is `accepted-catalog-unloadable`, and a host read failure while loading the candidate or reading its retained bodies is `catalog-unreadable`; only a candidate body that is absent, not a regular file or of another digest stays `retained-body-missing`. Every reason has a stable `code()` and `is_local()`: the command prints `candidate rejected: <reason>` for a refusal of the candidate and `candidate not checked: <reason>` for a local failure, exiting 1 either way.
- `reproduce-git-tags`:strictly load + policy-check accepted and candidate schema-5 catalogs, then take every Git-tag identity the candidate adds that the accepted catalog does not lock, ordered by registry, name and version, group them by registry, repository and tag, and fetch and package each group again in one resolution, as `lock` packages a tag, through the first-publication rules: the tag object, peeled commit, package directory, archive and source row must equal the locked ones, the packaged lock of a dependent must name the archive the candidate locks for every sibling it depends on, and a tag whose manifests name a registry the catalog retired is refused. A removed Git-tag identity that the accepted catalog does not lock is refused, because `lock` only tombstones an identity the generated lock already holds. The first failure stops the run and names the group and its cause; a change that adds no Git-tag identity reads no network.
- `self-publish-check`:checks of `self-publish/crates-io.toml` and `self-publish/crates-io.lock` against `registry/main.lock`, and against an accepted repository when one is given. The checks that compare with an accepted state need no network; with an accepted repository the command also checks the releases the run adds against the network: the annotated tag that `registry/main.lock` records on the repository's default branch, the crates.io owners and versions of each crates.io name, crates.io's category slugs and package rules, and the derivation against the recorded archive. A release is added when one of its self-published identities is new to the accepted catalog or its `crates-io.lock` entry is new to the accepted lock. A run without an accepted repository, or one that adds no release, reads no network. `<repository>` is the directory that holds `registry/` and `self-publish/`. A repository without `self-publish/` has nothing to check, unless the accepted repository has one: removing the state is refused.
- `self-publish-lock`:derive the crates.io package of every self-published identity of `registry/main.lock` that `self-publish/crates-io.lock` does not record yet, one fetch and one package per release tag, with the pinned Cargo in an isolated Cargo home; rewrite the workspace manifests and `Cargo.lock` for crates.io, refuse `[patch]`, `[replace]`, a dependency between two released crates of one tag other than a `path` dependency with `registry = "pkgre"` on the exact version, which becomes the sibling's crates.io name, a fork, and a first-party version crates.io lacks; prove every derived archive against the retained archive; then append the canonical entries atomically, once the offline checks accept the result. A run with nothing to derive changes nothing.
- `self-publish`:dry run, or with `--upload` the upload, of one release tag to crates.io, from a clean checkout whose `HEAD` is contained in the remote-tracking `origin/main`: the offline and network checks of `self-publish-check` for that release, the `pkgre` registry's own sparse index, crates.io's state of every crate version and of the packages outside the release that it depends on, Cargo's verified packaging of the missing crates while no token is in reach, then `cargo publish --no-verify` with the token in the environment of one process at a time, and a bounded wait for crates.io's index. It reports every crate version as published, published but yanked, missing, uploaded, abandoned, or different, uploads only what crates.io lacks, and never yanks, deletes, or changes owners. `<tag>` is a release tag such as `rust/v0.5.0`; `--git=<url>` chooses between several self-publishing repositories that use the same tag.

`<catalog>` is exclusive managed state:one `<registry>.toml` + generated `<registry>.lock` per registry; canonical generated `downloads.json`; exact referenced `categories/<registry>/<category>.toml`; paired `admissions/<batch>.{toml,lock}`; content-addressed `objects/{crates,rows}/`. Rows cover all locked identities; crate objects contain active retained-delivery archives:Git tags always, crates.io archives only when the registry declares `delivery = "retained"`. Retain every package key after its desired version/tag list becomes empty; deleting a required key, changing a name's registry/category home, or changing an existing identity's source fails closed.

Schema 5 requires catalog alias `main` at `sparse+https://rust.pkg.re/`; another canonical alias `staging` maps to `sparse+https://rust.pkg.re/r/staging/`. Every registry declares `audience` (`public` or `lan-public`) and may declare `delivery` (`redirect`, the default, or `retained`); a generated lock records the audience permanently and loading refuses a lock whose audience differs from the declaration. Registry/category/package identities are scoped by catalog registry. Dependency routing prefers a same-registry package home; absent that, exactly one external-registry home is required. The source category must explicitly permit the resolved target category. Existing registries/categories/homes are monotonic; future ones may be added.

One registry may contain mirror + publish names only when `download = "https://dl.rust.pkg.re/v1/<registry>/{crate}/{version}/{sha256-checksum}"` or same-host `"https://rust.pkg.re/v1/<registry>/{crate}/{version}/{sha256-checksum}"`. A single-source registry may use its fixed direct source endpoint. `downloads.json` is deterministically projected from every locked identity as exact `(registry, case-sensitive name, canonical version, archive SHA-256, closed redirect|retained delivery)` routes; the router never takes arbitrary destination URLs from this file.

Human admission manifests contain exact category/name/version or tag + optional typed evidence. Mirror apply currently accepts versions only. Generated admission locks retain complete recomputed facts; every package in a batch binds the SHA-256 of the same generated lock. Protected review/merge of the complete catalog PR is authorization; `automatic`/`review-required` only prioritize attention; `blocked` candidates cannot be applied.
